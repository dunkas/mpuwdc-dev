# Release safeguards

The user requires version control and a ZIP before every deployment. Before deploying, run relevant checks, commit the complete release, and create a dated ZIP tied to that commit. Preserve a rollback archive of the current deployed Hosting release and its Firestore/Storage rules when replacing them. Record commit ID, Firebase version IDs and SHA-256 hashes in a release manifest. Never include credentials, environment files, node_modules or logs in release archives. Keep prior dated archives.

Use the existing checkout; cloud tasks are already isolated. Deploy only the authorized development project mpuwdc-dev. A Hosting restoration must preserve unrelated education, calendar, candidate and member-account changes. The restored Finance House uses already-deployed finance callable services; do not replace all Cloud Functions with the obsolete functions/index.js. Recovered server source is in recovery/finance-functions as a reference.

The QR attendance release uses recovery/finance-functions as the configured source, with reviewed member-services.js and the original finance services preserved. Deploy only explicitly named functions: financeCommand, financeComplianceDaily, memberCard, attendanceData and attendanceCommand. Do not run an unqualified functions deployment: electionLegacy still depends on a private migration data file excluded from release archives, and unrelated deployed functions must retain their sources. The old functions/ directory is obsolete for deployment. Keep legacy attendance documents; Attendance Center bridges them without deleting or reseeding history. All new attendance mutations and QR issuance use password-verified server services, never direct Firestore client writes.

The finance governance release explicitly adds financeGovernance, staffAccess, memberZelle and financePublicLink. Its narrow deployment scope is those four functions plus financeCommand, financeData, financeFile, openFinanceSession and memberCard, Firestore rules and Hosting. Staff/member/payment corrections use audited password-protected server services; do not restore direct role or payment writes to fix a rejected client call. Messaging is a placeholder: never claim queued notifications are sent or put provider credentials into database/UI fields.

Member-ledger release scope: financeLedger, financeCommand, financeData, memberZelle and financeGovernance, Firestore rules and Hosting only. Never seed real dues rates, obligations or activated balances from example documents. Opening snapshots remain intact until individual Finance reconciliation/activation; see MEMBER-LEDGER.md.
